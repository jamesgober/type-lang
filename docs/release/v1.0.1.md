# type-lang v1.0.1

A patch release that fixes slow and deep cases in unification. There are no API changes.

## Fixed

- **The occurs check is linear on shared bindings.** Bindings such as `?i := Pair(?i+1, ?i+1)` describe a tree that doubles in size with each variable. The occurs check used to walk every path through it, so binding a variable to `?0` after 30 such steps took seconds, and each extra step doubled the time. Each binding is now searched once per check.
- **Unifying two such types is linear too.** `unify` now handles each pair of variables once per call instead of once per path.
- **Errors at the end of a long chain no longer overflow the stack.** A `Mismatch` or `Occurs` error used to resolve its payload recursively, so a mismatch at the end of a 200,000-step chain of bindings crashed. `resolve` is now iterative, and an error payload stops substituting variables once it is 64 levels deep or holds about 1,024 nodes. Past that, a bound variable is left in place, and `Unifier::resolve` expands it fully.
- **`Display` for `Type` is iterative**, so printing a deeply nested type is safe.
- **Restored state is checked (`serde` feature).** Deserializing a `Unifier` whose bindings form a cycle, such as `?0` bound to `?0`, used to succeed and then make later calls loop forever. It is now refused.

## Changed

- `unify` shortens chains of variables bound to variables as it walks them, so a long chain costs one walk instead of one per call.

## Still to know

A `Type` is an ordinary nested value. Its derived `Clone`, `PartialEq`, `Hash` and `Debug`, and dropping it, recurse once per level of nesting, so a type nested hundreds of thousands of levels deep (built by the caller, or returned by `resolve`) needs care.

MSRV is unchanged at Rust 1.85.
